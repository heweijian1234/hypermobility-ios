界面能用，但没替疼痛中的人想过。

HyperLog 的功能密度是够的：一键快记、九项 Beighton、多图、PDF 报告都在。问题出在核心路径被三个同等重量的圆按钮摊平了， 而真正值钱的「模式」被锁在二级页；严重度用交通灯配色，黄色文字在白底上只有 1.5:1，浅色模式基本看不见； 一键快记会写错数据——部位沿用上一条、程度写死 Moderate。下面 6 屏逐一对照，右侧是可落地的改法。

1P0

三个 64pt 圆按钮平分了注意力，还压住列表最后一行

证据
ContentView.swift:41-87，Quick Log 为 #AF52DE，＋ 与 More 同为 rgb(140,115,191)，全部 64×64
影响
「发作时一秒记下」是这个 App 唯一的核心动作，却和「More」同等视觉重量；.overlay 不参与 List 布局，最后一条记录会被圆按钮遮住
改法
底部收成一条 Log a flare 通栏主按钮（safeAreaInset），More 上移到导航栏；主按钮长按＝沿用上次部位直接落库＋撤销提示
5P0

首页只有流水账，价值最高的「模式」被锁在二级页

证据
首页仅 List；统计逻辑写在 DoctorReportView.swift:33-48
影响
用户每天打开看到的是四行流水，看不到「这周几次／最常哪个关节／比上周好没好」——而这正是他愿意每天打开的理由，也是给医生看的证据
改法
顶部加 7 日热力条＋本周计数＋最常见部位＋环比；数据层已有，只是换位置，不动模型

2P0

一键快记会静默写入错误数据

证据
ContentView.swift:111-119：bodyPart = entries.first?.bodyPart ?? "knee"，severity: 2 硬编码
影响
用户以为记下了肩膀，实际记成了膝盖；补细节时原始真实情况已经丢了。这条路走得越顺，医生报告越不可信——这是产品的地基问题，不是小 bug
改法
点击后不下沉，直接弹半屏确认卡：部位九宫格（默认继承上一条但高亮可见）＋严重度四段＋可选备注，Save 两次点击完成；Add details 跳完整表单并预填
3P0

部位选择 10 行、严重度文案 31 字符，都塞在同一个表单里

证据
EntryEditor.swift:29-41 用 .pickerStyle(.inline) 铺开 10 项；:42-50 四段控件含 "Severe (subluxation/dislocation)"
影响
发作时单手要滚 4–5 屏才填完；长文案在 iPhone 分段控件里必然截断成省略号，最严重的档位反而最看不清
改法
部位改 5×2 chips；严重度用四段短标签（Mild / Moderate / Significant / Severe），把「subluxation/dislocation」降级为选中 Severe 后出现的说明行

4P0

八段表单 + 10 行内联选择器 = 一次记录要滚 4 到 5 屏

证据
EntryEditor.swift 全 261 行，8 个 Section；部位 .inline 占 10 行；Beighton 又是 9 个 Toggle
影响
目标用户在「疼、单手、脑子糊」的状态下操作。分段控件里 Significant 和 Severe (subluxation…) 都被截断成 Signif…／Severe (s…，最严重档位反而最不可读
改法
「主体必填」与「细节可选」分离：部位 chips + 严重度四段常驻，其余折叠成 5 行带当前值的入口（点击展开子页），Beighton 收成一行摘要。首屏可完成，深度不丢
6P1

同一个产品里有三种紫，导航还是系统蓝

证据
Color.purple（#AF52DE）／Color(0.55,0.45,0.75) ×2／PDF 里 UIColor(0.45,0.3,0.7)；ContentView 未设 .tint，工具栏图标走默认 #007AFF
影响
深浅两套紫在同一屏出现，加上蓝色图标，品牌感被稀释；深色模式下 opacity(0.12) 底色会发脏；换色要改 4 处
改法
建 DesignTokens.swift 单一来源：paper / ink / accent 三组＋严重度四档，所有视图与 PDF 共用

6P1

报告页是「五行统计 + 两行同义按钮 + 三行说明」

证据
DoctorReportView.swift:32-84：5 行 statRow、两个都产出同一份 PDF 的大按钮、:81-83 三行 caption；数字用 .purple 无对比含义
影响
这页是产品最值钱的一屏（给医生看的证据），却最像后台管理界面：没有主视觉数字，条形图只存在 PDF 里，按钮语义重复让用户犹豫点哪个
改法
大号衬线数字＋环比、部位横条直接画在页面上、30 日热度条；主按钮收成一个 Send to doctor，另一个降为文字链；说明收进 What's included 折叠

改法
标签统一为名词短语（Severe / Hospital reset / Areas），括号说明移到 footnote

7P2

空状态是一份操作说明书，没有建立信任

证据
ContentView.swift:137-143：标题 Track your joints，正文两句话都在讲「点左下角、＋ 在哪」
影响

9P1

固定尺寸与 11pt 小字，大字号下会挤坏

证据
EntryRow 的 .frame(width:52,height:52)、.font(.caption2)（11pt）、FAB 内两行 9pt 文字；行内信息未合并 VoiceOver 标签
影响
Dynamic Type 调到 135% 以上时，胶囊和被写死的方形缩略图会互压；VoiceOver 会把一行记录读成 6 段碎片
改法
@ScaledMetric 驱动缩略图与按钮尺寸；次要信息靠颜色+字重双编码而非只靠小字；整行加 .accessibilityElement(children:.combine) 与一句朗读摘要

03

落地路线

按「影响核心路径的程度」排，不是按好看程度。P0 三项都能在不动数据模型的前提下完成。

P0本次迭代 / 影响地基
  • 修一键快记的数据正确性ContentView.quickLog() · 新增半屏确认卡
  • 底部收成一个主按钮safeAreaInset 替代三个 .overlay 圆按钮
  • 严重度换热力梯度4 档 token + 短标签，替换 traffic light
  • 表单首屏化部位 chips + 细节折叠，替代 10 行 inline picker
P1下一次迭代 / 建立记忆点
  • 首页加本周概览7 日热度条 + 最常见部位 + 环比
  • 抽 DesignTokens.swift颜色/字号/间距单一来源，PDF 同源
  • 报告页重排大号数字 + 页内条形图 + 单主按钮
  • 照片对比改 A/B 并排THEN / NOW + 胶片条换图
  • 动态字体与 VoiceOver@ScaledMetric + 整行合并朗读
P2打磨 / 有余力再做
  • 空状态改写共情主张 + 隐私保证 + 主 CTA
  • 自定义部位选择器other:xxx 用 chips 承载
  • 深色模式校色paper/ink 需反向 token，不能只靠 opacity
  • 导语本地化注释写着「测试期中文版」，UI 仍全英文
04

交接要点

只列会被直接抄进代码的部分；都是 SwiftUI 原生能力，不引依赖。

1. Token 单一来源

// DesignTokens.swift enum Theme { static let paper = Color(hex: 0xF6F3EC) static let ink = Color(hex: 0x1B1A17) static let ink2 = Color(hex: 0x5F5C53) static let accent = Color(hex: 0x22344D) // 严重度：单一色相梯度，替换 green/yellow/orange/red static let sev: [Color] = [ Color(hex: 0x8A6E2B), // Mild Color(hex: 0xA5661F), // Moderate Color(hex: 0xA34A24), // Significant Color(hex: 0x7C2D1C) // Severe ] }

替换点：ContentView.severityColor、两处 Color(red:0.55…)、DoctorReportView 里的 PDF purple。

2. 底部主按钮不遮内容

// 替换三个 .overlay(alignment:) List { … } .safeAreaInset(edge: .bottom) { LogBar() // 50pt 主按钮 } // 长按 = 沿用上次部位直接落库 + 可撤销 .onLongPressGesture { quickLogWithUndo() }

为什么不是 overlay：overlay 不参与布局，列表最后一行会被永久遮住（现状就是这个行为）。

3. 严重度控件换掉 segmented

// 四段短标签 + 动态说明，替代被截断的长文案 HStack(spacing: 0) { ForEach(0..<4, id: \.self) { i in Text(short[i]) .frame(maxWidth: .infinity, minHeight: 44) .background(severity == i ? Theme.sev[i] : .clear) .foregroundColor(severity == i ? .white : Theme.ink2) .onTapGesture { severity = i } } } Text("Severe = it slipped out or dislocated.") .opacity(severity == 3 ? 1 : 0)

顺手解决了 "Severe (subluxation/dislocation)" 在分段控件里被吃掉的问题。

4. 大字号与朗读

// 固定 52pt 缩略图改随字号缩放 @ScaledMetric(relativeTo: .body) var thumb: CGFloat = 50 // 整行合成一句，而不是 6 段碎片 .accessibilityElement(children: .combine) .accessibilityLabel( "\(part), \(severityLabel), \(dateText)")

验证：把 Dynamic Type 调到 135% 与 200% 各看一遍首页与表单，胶囊不换行、缩略图不压字即可。
